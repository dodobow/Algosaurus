# 검증 기록 (2026-11-25 갱신)

## 기존 UI 복원 검증

사용자의 요청에 따라 UI 기준을 전환 전 `8baa49b`로 맞췄어. 세 CSS 파일의 원본 일치, 모듈 로딩을 제외한 설정 HTML의 정적 구성 일치를 회귀 검사해. 원래 프로필/목표 카드·문제 번호/제목 span·32단계 색상·태그 배지/한국어 툴팁·내실 표시를 복원했고, 추가 분석 버튼을 제거했어.

실제 API와 Chrome 저장소 대역의 브라우저에서 dodobow 프로필의 두 칸 카드, 기본 8개·취업 맞춤 10개 태그의 자동 분석, 티어 SVG 로딩과 한국어 툴팁, 목표 추천 BOJ 17374와 약점 추천 BOJ 28709 표시를 확인했어. 모드 변경 중 진행 중이던 추천이 무효화되는 것도 확인했어. 내실 지표는 87.87로 기존 숫자 슬롯에 표시돼.

최신 자동 검사 결과는 Python 37개·Node 18개 통과야. 유효한 같은 설정의 분석을 다시 요청해도 문제 검색을 반복하지 않는 회귀 테스트를 추가했어. 시각 지표의 값은 v4의 정확한 계산을 유지해. 실제 Chrome 확장 자체 설치·코드 제출은 여전히 미검증이야.

## 2026-11-25 실제 인증 API 검증

사용자가 로컬 `.env`에 설정한 앱 인증정보로 검증했어. 인증정보는 출력하거나 Git·확장 패키지에 포함하지 않았어.

- 실제 프로필: solved.ac `dodobow`, 인증된 BOJ 계정 `dodobow`, Diamond V(21), 레이팅 2224, 해결 1738문제.
- 취업 목표·난이도 +1: 레벨 9~16 추천. 실제 목표 추천 BOJ 1138 「한 줄로 서기」(9), 약점 추천 BOJ 21737 「SMUPC 계산기」(10, `string`)를 받았어.
- 두 추천 문제를 별도 `@dodobow id:<문제 세트>` 검색으로 대조했을 때 해결 결과가 0개였고 diagnostics도 없었어.
- 기본 8개 태그·취업 맞춤 10개 그룹을 실제 API로 분석했어. 공식 태그 레이팅도 API 응답 그대로 표시됐어. 내실은 200 고유 레이팅 대상 세트로 87.87%였어.
- 실제 데이터 기준 기본 그룹 약점은 구현·문자열, 취업 맞춤 그룹 약점은 문자열·다양한 테크닉이었어. 이 결과는 자체 상대 지표이며 객관적인 실력 평가가 아니야.
- 실제 HTML/JS와 실제 API, Chrome 저장소 대역을 연결한 브라우저에서 첫 실행 → dodobow 조회 → 취업 목표·난이도 +1 → 분석 → 추천까지 확인했어.
- 팝업의 BOJ 18223 「민준이와 마산 그리고 건우」 링크를 눌러 새 탭의 실제 문제 본문·입력·출력을 확인했어. 이후 약점 추천 BOJ 1856 「단어 게임」도 팝업에 표시됐어.
- BOJ 1138번도 실제 문제 본문이 열렸어. 11월 20일에 관찰했던 재개 연기 안내 상태는 현재 검증 결과로 대체해.

남은 미검증 항목은 **실제 Chrome 확장 자체 설치·host permission·Chrome storage 이벤트**와 BOJ 코드 제출이야. 연결 가능한 브라우저는 IAB뿐이어서 화면은 Chrome API 대역을 사용했어. 실제 solved.ac API 응답과 BOJ 목적지 검증에는 모의 데이터를 사용하지 않았어.

## 실제 응답에서 발견해 수정한 문제

첫 실분석에서 `/tags`의 aliases에 옛 키가 있을 거라는 가정이 틀렸음을 확인했어. 모의 카탈로그가 코드의 그룹 설정에서 생성되어 이 문제를 놓쳤어. 그룹에 쓰던 33개 옛 키를 실제 v4 canonical 키로 수정하고, 테스트 카탈로그를 API에서 받은 72개 관련 태그의 독립 스냅샷(`tests/data/tags-v4.json`)으로 교체했어.

다른 태그의 별칭이 정식 키와 겹치는 경우도 있었어. `stat`의 별칭 `combinatorics`가 정식 `combinatorics` 키를 덮어쓰지 않게 우선순위를 고쳤고 회귀 테스트를 추가했어. 수정 뒤 기본·취업 맞춤 실분석이 모두 통과했어.

## 이전 2026-11-20 확인 기록

- 공식 Backstage 문서 페이지와 해당 앱이 사용하는 `/api/v4/openapi`를 직접 읽었어.
- 브라우저에서 v4 업데이트·공식 API 공개 공지 본문을 확인했어.

당시에는 앱 인증정보가 없어 실제 인증 API를 검증하지 못했어. 이 항목은 위 11월 25일 실제 검증으로 해소했어.

## 모의 응답 기반 자동 검증

Python 단위·실제 localhost HTTP 통합 테스트 37개, Node 테스트 18개를 사용해. upstream은 대역이며, 태그 메타데이터는 실제 API 스냅샷을 사용해. 자동 테스트 중 외부 API를 호출하지 않아.

- 앱 인증 헤더, 검색 인코딩, 인증정보 미설정, 네트워크 실패·잘못된 JSON·429와 앱 전체 대기
- 고정 기능 경로, 임의 URL/검색식·중복 파라미터 거부, Host·Origin 제한
- solved.ac/BOJ 핸들 구분, 명시적인 풀이 제외 검색식, 목표·난이도 범위와 미리보기 일치(전체 480조합)
- solved.ac 세트/소문제 식별자와 서로 다른 BOJ URL 사용, 위험한 외부 링크 거부, 빈 결과·비공개 티어
- `/tags` 별칭을 canonical 키로 변환, 기본 8개와 목표별 10개 그룹, 100자·8항 쿼리 분할
- 소문제·중복 세트 최고 난이도, 평점 제외 문제 제거, 4페이지를 넘어가는 고유 세트 수집, 부족 데이터·불완전 페이지·조회 한도
- 분석 → 같은 설정의 약점 추천, 계정·설정별 캐시 분리·15분 만료·동시 분석 공유·부분 실패 시 캐시 미생성
- 기존 저장값과 인증된 BOJ 연결에 따른 마이그레이션, 원본 설정 보존, 새 계정 설정 덮어쓰기 방지
- 실제 팝업 모듈을 DOM/Chrome API 대역에서 실행해 첫 사용, 뒤늦은 프로필·추천 응답 무효화, 다른 설정 반영, 약점 데이터 없음과 429 메시지를 검증

`tools/check.py`로 manifest/HTML/ES 모듈 참조, JS 문법, 런타임의 v3·공용 프록시·시크릿 헤더 제거를 검사했어. `git diff --check`도 확인했어.

## 브라우저에서 확인한 화면 흐름

테스트 서버는 실제 팝업·설정 HTML/JS를 그대로 제공하고, 테스트 전용 shim이 Chrome 저장소를 localStorage로 대체해. 따라서 **Chrome 확장 런타임 자체 설치 검증과는 구분**해야 해.

1. 첫 실행 안내 → `solved_name` 조회 → 연결된 다른 BOJ 계정 `boj_other` 표시
2. 목표 맞춤 추천 → API 제공 BOJ 1000 링크 → 실제 외부 탭 열기
3. 설정 화면에서 분석 실행 → 기본 8개 태그 결과와 내실 81.14% 표시(모의 데이터)
4. 팝업 약점 보충 → 추천 링크 표시
5. 다른 탭에서 목표 변경 → 이전 분석·추천 즉시 무효화 → 재분석 안내
6. 취업 목표·목표 맞춤 모드 → 10개 태그군 분석 표시

실제 Chrome 확장의 host permission·storage 이벤트는 압축 해제된 확장으로 최종 확인할 항목이야. IAB에서는 확장 설치 대신 위 대역 환경으로 검증했어.
