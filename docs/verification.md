## 자동 분석의 반복 제한 수정

로컬 60단위 예산에서 자동 분석을 반복하면 RATE_LIMITED가 재발하던 흐름을 모의 예산으로 재현했어. 난이도·기본 모드의 목표를 분석 키에서 제외하고, UI에서도 이 변경에는 진행 중인 분석과 결과를 유지하도록 수정했어. 맞춤 모드의 목표와 계정이 달라지면 기존 응답은 계속 무효화해.

로컬 예산은 늘리지 않고 요청당 최대 10초간 충전을 기다리도록 수정했어. 실제 upstream 429/Retry-After는 별도 대기로 유지하고 자동 재전송하지 않아. 검증한 성공 페이지를 계정 ID·검색식·페이지별로 재사용하고 같은 페이지의 동시 조회를 공유해. 중간 실패의 부분 점수는 저장하지 않고 성공한 앞 페이지들만 재사용해. 프로필도 30초간 재사용해.

반복 제한 수정 당시 자동 검사는 Python 50개·Node 23개 통과였어. 모의 검증에는 다음을 포함해.

- 초기 분석 → 난이도 변경·기본 목표 변경에서 추가 외부 호출이 없음, 요청별 응답 settings 유지
- 맞춤 목표 연속 변경 시 60단위가 소진돼도 충전을 기다려 완료, 공통 페이지 재호출 없음
- 페이지 중간에 429가 난 뒤 재시도할 때 앞의 성공 페이지를 재호출하지 않음
- 실제 429와 앱 전체 cooldown, 로컬 대기 최대 10초, 캐시 TTL·LRU 상한·동시 로더 공유
- 프로필 ID 재할당/다른 핸들 분리, 잘못된 문제 데이터의 캐시 오염 방지, total 변경 시 해당 캐시 폐기
- 실제 설정 JS를 DOM·Chrome 대역으로 실행: 난이도 변경 중 분석 취소/추가 요청 없음, 결과 표시, 모드·계정 변경 시 늦은 응답 폐기, 맞춤 목표 연속 변경 합치기
- UI 원본 CSS/정적 HTML 계약 및 기존 프로필·추천·마이그레이션 회귀 검사 유지

## 모의 응답 기반 자동 검증

Python 단위·실제 localhost HTTP 통합 테스트 57개, Node 테스트 30개를 사용해. upstream은 대역이며, 태그 메타데이터는 실제 API 스냅샷을 사용해. 자동 테스트 중 외부 API를 호출하지 않아.

- 앱 인증 헤더, 검색 인코딩, 인증정보 미설정, 네트워크 실패·잘못된 JSON·429와 앱 전체 대기
- 고정 기능 경로, 임의 URL/검색식·중복 파라미터 거부, Host·Origin 제한
- solved.ac/BOJ 핸들 구분, 명시적인 풀이 제외 검색식, 목표·난이도 범위와 미리보기 일치(전체 480조합)
- solved.ac 세트/소문제 식별자와 서로 다른 BOJ URL 사용, 위험한 외부 링크 거부, 빈 결과·비공개 티어
- `/tags` 별칭을 canonical 키로 변환, 기본 8개와 목표별 10개 그룹, 100자·8항 쿼리 분할
- 소문제·중복 세트 최고 난이도, 평점 제외 문제 제거, 4페이지를 넘어가는 고유 세트 수집, 부족 데이터·불완전 페이지·조회 한도
- 분석 → 동일 태그 그룹의 약점 추천, 계정·실제 분석 조건별 캐시 분리·15분 만료·동시 분석 공유·부분 실패 시 정상 점수 미생성 및 성공 페이지 재사용
- 기존 저장값과 인증된 BOJ 연결에 따른 마이그레이션, 원본 설정 보존, 새 계정 설정 덮어쓰기 방지
- 실제 팝업 모듈을 DOM/Chrome API 대역에서 실행해 첫 사용, 뒤늦은 프로필·추천 응답 무효화, 다른 설정 반영, 약점 데이터 없음과 429 메시지를 검증
- 확장 ZIP에서 서버·시크릿·테스트 제외

`tools/check.py`로 manifest/HTML/ES 모듈 참조, JS 문법, 런타임의 v3·공용 프록시·시크릿 헤더 제거를 검사했어. `git diff --check`도 확인했어.

## 브라우저에서 확인한 화면 흐름

테스트 서버는 실제 팝업·설정 HTML/JS를 그대로 제공하고, 테스트 전용 shim이 Chrome 저장소를 localStorage로 대체해. 따라서 **Chrome 확장 런타임 자체 설치 검증과는 구분**해야 해.

1. 첫 실행 안내 → `solved_name` 조회 → 연결된 다른 BOJ 계정 `boj_other` 표시
2. 목표 맞춤 추천 → API 제공 BOJ 1000 링크 → 실제 외부 탭 열기
3. 설정 화면에서 분석 실행 → 기본 8개 태그 결과와 내실 81.14% 표시(모의 데이터)
4. 팝업 약점 보충 → 추천 링크 표시
5. 다른 탭에서 목표 변경 → 이전 분석·추천 즉시 무효화 → 재분석 안내
6. 취업 목표·목표 맞춤 모드 → 10개 태그군 분석 표시

실제 Chrome 확장의 host permission·storage 이벤트는 압축 해제된 확장으로 최종 확인할 항목이야. IAB에서는 확장 설치 대신 위 대역 환경으로 검증했어.

## 재현 명령

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
npm test
python tools/check.py
python tools/package_extension.py
```

localhost HTTP 테스트는 이 작업 환경의 sandbox에서 TCP 연결이 차단되어 권한 확장 후 실행했어. 일반 로컬 개발 환경에서는 별도 관리자 권한이 필요하지 않아.
