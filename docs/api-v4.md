공식 자료:

- https://backstage.solved.ac/api/v4/openapi

문서의 원본 OpenAPI와 공식 Backstage 클라이언트의 검색 필터 정의를 직접 확인했다. 공지 두 개는 브라우저에서 본문을 읽었다. 기존 AC 레이팅 도움말은 2025년 기준이라는 경고가 있어 최신 공지와 API 응답을 우선한다.

11월 25일에는 실제 앱 인증으로 프로필·문제·태그 API도 검증했어. 최신 OpenAPI에는 `logoDarkUrl`, OJ별 `solverCount`, 문제의 `mergedFrom`·`credits`가 추가됐고, 기존에 읽는 필드는 유지됐어. 추가 필드는 표시·계산에 필요하지 않아 그대로 허용해.

## 인증과 호출 제한

모든 요청은 앱의 x-client-id, x-client-secret 헤더를 요구한다. public 작업은 사용자 토큰 없이 가능하다. user 작업은 해당 scope의 Bearer 토큰이 필요하다. OAuth는 authorization code + PKCE S256 방식이지만, 공개 프로필과 타인의 풀이를 명시한 검색에는 필요하지 않다. 현재 문서에는 비로그인 검색이 모든 앱의 현 상태라고 명시돼 있어 OAuth를 우회 수단으로 가정하지 않는다.

호출 예산은 기본 600단위, 초당 2단위 충전이다. 앱과 호출자 예산을 함께 적용하고 앱 배율에 따라 변한다. 일반 요청 1, 문제 검색 3, 투표 목록 2단위다. 429의 Retry-After와 X-RateLimit-Limit/Remaining을 제공한다. 서버는 더 보수적인 60단위·초당 1단위와 동시 3요청 제한을 유지한다. 로컬 예산이 부족하면 락 밖에서 충전을 기다렸다 전송하며, 요청당 10초 대기를 넘으면 로컬 대기 오류를 반환한다. 실제 429를 받으면 앱 전체 외부 호출을 Retry-After 동안 차단하고 별도 UPSTREAM_COOLDOWN 오류로 구분한다. 실패한 외부 요청을 자동 재전송하지 않는다.

비로그인 검색은 100자·8항 제한이다. 임의 q를 클라이언트에서 받지 않고 서버가 제한 내 검색식을 조립한다. 목표별 여러 태그는 분석 후 서버에 저장한 짧은 개별 태그로 순차 추천한다.

## 검색과 응답

공식 필터 정의: `*` 난이도(1~30), `%ko` 한국어 문제문 존재, `@handle`/`s@handle` 특정 solved.ac 사용자의 풀이, `!`/`-`/`~` 부정, `in:boj` BOJ 수록, `solvable_in:boj` BOJ 제출 가능. `@me`는 사용자 토큰의 사용자이므로 사용하지 않는다. 없는 계정을 제외하면 아무것도 제외하지 않을 수 있으므로 프로필을 먼저 확인하고 검색 diagnostics도 검사한다.

`GET /problems?q=...&page=1&sort=level&direction=desc`는 고정 50개 페이지, `problems`, `total`, `page`, `pageSize`를 반환한다. 태그는 `key`와 `aliases`, 부모 태그를 `/tags`에서 확인한다. 문제 상세 경로는 `/problems/{problemId}?sub={subId}`다. 목록의 `id`는 내부 항목 식별자이고 `problemId`와 `subId`가 문제 세트·소문제를 나타낸다. 상세 `ojLinks`의 실제 URL을 사용하며 BOJ ID를 solved.ac ID로 추정하지 않는다.

프로필은 `/users/{handle}`이며 `ojAccounts`가 연결된 OJ 계정이다. solved.ac 핸들과 BOJ 핸들은 다를 수 있다. `tier`는 null일 수 있다. 프로필의 `rating`, `tagRatings` 및 레이팅 구성 값을 그대로 사용한다.

## 최소 구성

Vanilla JS ES 모듈 + Python 3.11 이상 표준 라이브러리 서버다. 브라우저 → 127.0.0.1 고정 서버 → solved.ac 고정 API 경로로 호출한다. 시크릿은 서버 환경변수에만 둔다. 서버는 외부 인터페이스에 바인딩하지 않으며, Host와 확장 Origin을 검사한다. 외부 URL, 임의 API 경로, 임의 검색식은 받지 않는다. 이 서버를 공용 호스팅할 경우 인증·HTTPS·서버 배포 구성을 별도로 설계해야 한다.

## 분석 의미의 변경

- 공식 AC 레이팅과 기본 모드 태그의 공식 레이팅은 프로필 응답 값을 그대로 표시해. 기여 보너스 제거·문제 수 보너스 250 상한을 옛 공식으로 다시 계산하지 않아.
- 맞춤 태그군의 옛 `2 × 상위 50 난이도합 + 200 × (1 − 0.99^count)`는 공식 레이팅으로 볼 근거가 없어 삭제했어. 이제 레이팅 대상인 **상위 50 고유 문제 세트의 난이도합**을 별도 지표로 사용해. 범위는 0~1500이고 공식 티어로 변환하지 않아. 태그군 간 중첩과 그룹 크기가 점수에 영향을 주므로 객관적인 실력 평가가 아니야.
- 기본 8개·목표 맞춤 10개 그룹은 실제 `/tags`에서 확인한 v4 canonical 키를 사용해. `aliases`는 검색 별칭이며 옛 키가 항상 포함되지는 않아. 예를 들어 `impl`의 aliases는 빈 배열이야. 정식 키를 먼저 등록하고 별칭은 정식 키를 덮어쓰지 않게 처리해. 긴 그룹은 100자·8항 이내 쿼리로 나누고 합집합에서 다시 중복을 제거해. 일부 태그를 찾지 못하면 0점으로 넘기지 않고 오류를 반환해.
- 문제 목록에서 `givesNoRating=false`, 난이도 1~30인 항목만 계산해. 세트는 `problemId`, 소문제는 `subId`로 구별하고 같은 세트에서 가장 높은 **조회 조건에 맞는 해결 소문제**의 난이도만 사용해. BOJ 원본 번호와 solved.ac 문제 세트 번호를 동일시하지 않아.
- 내실은 전체 OJ의 레이팅 대상 해결 문제에서 상위 200 고유 세트를 직접 조회해 계산해. 언어와 OJ는 분석에서 제한하지 않고 BOJ 추천에서만 제한해. API의 전체 레이팅 합에서 특정 페이지를 빼던 방식은 제거했어.
- 정렬한 50개씩의 난이도합을 A/B/C/D라 하면 지표는 `50 × ((C+D)/(A+B) + (C+D)/(2B))` %야. 200세트 미만, 분모 0, 데이터 누락, 호출 실패에는 점수 대신 부족/오류를 표시해. 이는 난이도 균형 지표이며 실력을 보장하지 않아.
- 한 검색당 최대 16페이지를 조회해. 목록 total이 바뀌거나 페이지가 누락되거나 한도 내 필요한 고유 세트 수를 확보할 수 없으면 오류로 처리해. 일부 데이터로 정상 점수를 만들지 않아.
- 약점은 태그군 평균 난이도합보다 10% 넘게 낮은 그룹이야. 평균이 0이면 판단 불가야. 약점 추천은 낮은 점수 그룹부터 최대 3개의 canonical 태그를 개별 검색해 호출 비용을 제한해. 조회한 일부 태그에 결과가 없는 경우를 전체 약점 문제 소진으로 표현하지 않아.
- 서버의 성공한 분석만 최대 64개, 15분간 메모리에 저장해. 키는 버전·숫자 프로필 ID·solved.ac 핸들·모드·맞춤 모드의 목표야. 난이도는 추천에만 영향을 주므로 분석 키에서 제외하고, 기본 모드는 목표에 관계없이 같은 8개 그룹을 재사용해. 같은 키의 동시 분석을 공유하되 응답의 settings는 각 요청의 현재 설정으로 돌려줘. 약점 추천은 동일한 키를 사용하고 추천 범위에는 현재 목표·난이도를 적용해.
- 분석 페이지는 버전·프로필 ID·검색식·페이지별로 최대 512개, 15분간 재사용해. 검색식에 계정과 태그가 포함되므로 다른 계정·다른 그룹을 혼합하지 않아. 페이지 형식·문제 데이터·diagnostics를 검증한 뒤 저장하고, 중간 실패 때 이미 성공한 페이지를 버리지 않아. 같은 페이지의 동시 조회도 하나로 합쳐서 화면에서 취소한 작업과 새 작업의 중복 호출을 줄여. 전체 분석이 완료되기 전에는 정상 분석 점수나 약점 결과를 저장하지 않아. 페이지 사이 total이 달라지면 해당 검색의 페이지 캐시를 비우고 오류를 반환해.
- 프로필은 요청 핸들별 최대 64개, 30초간 재사용하고 같은 핸들의 동시 조회를 공유해. 따라서 프로필 변경 반영에는 최대 30초가 걸릴 수 있어. 태그 메타데이터는 계정과 무관한 자료로 24시간 캐시해. 모든 캐시는 메모리에만 존재하며 서버 재시작 뒤 약점 추천은 재분석을 요구해. 실패 응답은 캐시하지 않아.

## 기존 UI 유지

UI 기준은 전환 전 커밋 `8baa49b`야. 공통·팝업·설정 CSS와 설정 HTML의 정적 구성을 원본으로 유지해. 원래의 두 칸 프로필, 문제 번호/제목, 태그 이름·배지·숫자·한국어 hover 툴팁을 사용해. 추가했던 분석 버튼은 제거하고 설정 페이지 진입과 실제 분석 조건 변경 시 자동 분석해. 빠른 연속 변경은 300ms 간격으로 합쳐. 난이도와 기본 모드의 목표 변경에서는 표시한 결과·진행 중인 분석을 유지하고 추천 범위만 갱신해. 계정·모드·맞춤 목표가 달라지면 이전 응답을 무효화해.

공식 태그 레이팅은 기존 티어 색상과 배지를 사용해. 목표 맞춤 배지는 `score / count`로 구한 분석 대상 문제 세트의 평균 난이도를 가장 가까운 정수 문제 티어로 반올림해(정확히 .5면 위로). 예를 들어 50세트의 합이 791이면 평균 15.82 → 난이도 16(Platinum V) 배지야. 카드 숫자는 난이도합 791을 그대로 유지해. alt/툴팁에서 평균 문제 난이도 배지와 공식 레이팅이 아님을 설명해. 데이터가 없거나 평균을 안전하게 계산할 수 없으면 Unrated를 유지하고, NaN/Infinity는 표시하지 않아. 이는 문제 난이도를 요약한 배지이며 사용자·태그 공식 티어가 아니야. 맞춤 점수 합을 공식 레이팅 임계값으로 변환하지 않아. 계정의 서비스 구분도 기존 이름 툴팁으로 제공해. 카드 배치·CSS·정적 HTML은 변경하지 않아.

티어 SVG는 원본과 같은 파일을 확장에서 직접 참조하는 로컬 자산으로 보존해. 아카이빙 웹 진입점이나 캡처 기능은 복구하지 않아.

## 기존 설정과 비동기 처리

기존 `solvedId`는 BOJ 핸들일 수 있어 최초 전환에서는 자동 연동하지 않아. 사용자가 solved.ac 핸들로 조회하면 `ojAccounts`의 인증된 BOJ 핸들이 옛 ID와 일치할 때만 기존 goal/diff/mode를 새 핸들 키로 복사해. 새 설정이 이미 있으면 덮어쓰지 않고 옛 키도 지우지 않아. 연결을 확인하지 못하면 새 계정은 기본 설정으로 시작해. 옛 tier/rating 합과 weakTags 캐시는 읽지 않아.

팝업과 설정에서 요청 세대 번호와 AbortController를 함께 사용해. 결과를 반영하기 전에 현재 계정과 설정도 다시 읽어 비교해. 다른 탭의 storage 변경도 기존 분석과 추천을 무효화해. 서버 시크릿은 확장 ZIP 허용 목록에서 구조적으로 제외해.
